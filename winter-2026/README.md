## 夏の申込から進化した点

| | 夏（スプレッドシート＋フォーム） | 冬（ポータル） |
| --- | --- | --- |
| お子さん・学年 | 保護者が入力 | ポータルの登録内容から自動。学年に合う講座だけを表示 |
| 講座選び | 講座選択の画面で選ぶ | スマホは見やすいカード、PCは時間割。期間・日付・集団/個別・キーワードで絞り込み。全日程・持ち物・残席をその場で確認 |
| 料金 | 画面で家庭の合計を計算（お子さんごとの内訳は保存されない） | 選ぶたびに定価・講座数割引・きょうだい割引・合計を表示。サーバーで同じ計算をやり直して保存 |
| 定員 | 申込一覧から集計シートで再計算 | 申込の瞬間に確認。同時に申し込んでも定員を超えない（実際のデータベースで試験済み） |
| 変更・取消 | 仕様書に保護者自身による変更の記載なし | 保護者が自分で選び直して再送信。残席・料金も自動で更新 |
| 受付の控え | 申込番号＋メール認証のマイページ | 受付番号（W26-XXXX-XXXX）をその場で表示。ポータルでいつでも確認 |
| 職員の管理 | 申込数集計シート（満席赤・7割超黄） | 件数タイル、棒グラフ（7割で黄・満席で赤）、締切・再開・定員変更を画面から。操作はすべて履歴に残る |
| 請求 | 承認後にシートから請求メールを送信 | 既存の季節講習の請求・出席・入金配賦とそのままつながる |

## 未完了・公開前に決めること

1. **本番への反映は未実施**：DB への migration 適用、PR、Render のデプロイ、公開はしていません（承認後の作業）。
2. **1回・2回だけの講座の料金**：今の仕組みでは「1講座分（3回分）」の料金でしか受け付けられません。料金を決めるまでは「準備中」のままです。
3. **講座の確定**：時間割の講座のうち多くがまだ下書きです。確定と、標準外講座の料金確認が必要です。
4. **受付メール**：未実装です（送信済みとは表示しません）。
5. **教科での絞り込み・定員管理専用の権限・履歴閲覧画面**：未実装です（権限は既存の「時間割の管理」、履歴は DB に保存）。
6. **実際のログイン環境での確認**：確認版は模擬データです。本番相当（staging）での確認は未実施です。
